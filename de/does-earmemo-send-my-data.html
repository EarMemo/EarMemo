EarMemo › Was die App ins Netz sendet

Sendet EarMemo meine Daten irgendwohin? Hier sind alle Netzwege der App

Drei Wege, und keiner trägt Ihre Bibliothek hinaus. Die optionale Wi-Fi-Übertragung startet einen kleinen Webserver auf dem iPhone und bleibt in Ihrem eigenen Netzwerk. Pro kaufen, Kauf wiederherstellen und das Bewertungsfenster laufen über Apple StoreKit, also Apples Code im Gespräch mit Apple. Die Taste EarMemo bewerten übergibt iOS eine URL, geöffnet wird sie von der App-Store-App. Import, Wiedergabe, Notizen, Statistik und Markdown-Export nutzen keinen dieser drei Wege.

EarMemo hat keinen eigenen Server, es gibt also gar keine Adresse, an die Audio, Notizen oder Hörverlauf gehen könnten. Unten steht die vollständige Aufstellung, danach, was Sie prüfen können, ohne mir ein Wort zu glauben.

Aktualisiert am 15. Oktober 2026 · Von Fan YANG, dem Entwickler von EarMemo.

Was in der App gar nicht vorkommt

  • Kein Kontosystem, also keine Anmeldung und nichts, was Sie identifiziert.
  • Keine Analyse, keine Ereignisprotokolle, kein Crash-Reporter.
  • Keine Fernkonfiguration, kein beim Start geladener Feature-Schalter, keine A/B-Zuteilung.
  • Keine Werbung und kein Attributions-SDK.
  • Kein SDK von Dritten, keines. Das Projekt hat keine Abhängigkeitsdatei für CocoaPods, Carthage oder Swift Package Manager, und jedes eingebundene Framework stammt von Apple: AVFoundation, SwiftUI, StoreKit, WidgetKit, AppIntents, Network und so weiter.
  • Kein WebView, also kann in der App keine entfernte Seite geladen werden.

Vier Wege, das von außen zu prüfen

Eine Datenschutzaussage, die Sie nicht prüfen können, ist nur ein schöner formuliertes Versprechen. Nach Aufwand sortiert; für den ersten Weg brauchen Sie nichts außer Ihrem iPhone.

  1. App-Datenschutzbericht einschalten. Einstellungen → Datenschutz & Sicherheit → App-Datenschutzbericht. Danach hält iOS pro App fest, welche Domains sie kontaktiert hat. Nutzen Sie EarMemo ein paar Tage normal und sehen Sie sich den Eintrag an: eine von EarMemo kontaktierte Domain stünde dort.
  2. Das eigene DNS-Protokoll ansehen. Wenn Sie Pi-hole, NextDNS oder einen Router mit Protokoll betreiben, lassen Sie es offen, während Sie importieren, abspielen, Notizen schreiben und exportieren. Eine Namensauflösung ist der erste Schritt, bevor eine App einen Server erreicht, und vor dem eigenen Resolver kaum zu verbergen.
  3. Das Gerät hinter einen Proxy setzen. Richten Sie es auf Proxyman, Charles oder mitmproxy am Rechner und gehen Sie die ganze App durch. Verkehr sehen Sie allein beim Kauf, und der ist Apples: StoreKit läuft außerhalb des App-Prozesses.
  4. Flugmodus ab dem ersten Start. Installieren, Flugmodus an, dann die App zum ersten Mal öffnen: aus der Dateien-App importieren, abspielen, Notizen schreiben, Statistik ansehen. Eine App, die einen Server braucht, bleibt beim ersten Start gern hängen oder mahnt. Ausführlich steht dieser Weg auf der Seite zur Offline-Wiedergabe ohne Konto.

Zwei weitere Belege liegen bei Apple, nicht bei mir. Das Datenschutzlabel von EarMemo im App Store lautet Keine Daten erfasst, und das Datenschutzmanifest in der App erklärt Tracking als deaktiviert, mit leerer Liste der Tracking-Domains und leerer Liste der erfassten Datentypen. Beides sind Erklärungen, an denen Apple Entwickler festhält – eine andere Art Beleg als ein Satz auf einer Website.

Die Prüfung, die auf meiner Seite läuft

Diese können Sie nicht ausführen, Sie haben den Quellcode nicht. Sie ist trotzdem der Grund, warum die Liste oben bei drei bleibt: Die Projektregel lautet, dass diese Suche leer zurückkommen muss, bevor Netzwerkcode geschrieben wird, und sie steht in den Anweisungen, nach denen ich entwickle.

$ grep -rn "URLSession\|URLRequest\|dataTask" --include="*.swift" \
    Sources ShareExtension SleepTimerWidget Shared
$   # keine Treffer – 21.10.2026

URLSession ist der Weg, auf dem eine solche App von sich aus nach draußen fragt, und im Projekt steht sie an keiner Stelle. Das einzige import Network ist der Wi-Fi-Übertragungsserver, und die einzige externe URL, die die App öffnet, ist ihre eigene App-Store-Seite – die anderen drei Stellen, die iOS eine URL übergeben, öffnen alle die Einstellungen von iOS.

Was der Wi-Fi-Übertragungsserver ist, auch der unangenehme Teil

Ein kleiner HTTP-Listener auf dem iPhone, gebunden an einen Port zwischen 8080 und 8090, per Bonjour als _earmemo-transfer._tcp angekündigt, damit Ihr Rechner ihn ohne eingetippte Adresse findet. Er startet, wenn Sie den Bildschirm für die Wi-Fi-Übertragung öffnen, und stoppt, wenn Sie ihn verlassen. Während er läuft, kann jeder im selben Netzwerk, der die Adresse öffnet, die Dateiliste sehen und hochladen. Das Token, das die Seite pro App-Start mitbringt, hält eine fremde Seite in Ihrem Browser davon ab, die API aufzurufen – nicht eine Person in Ihrem Netzwerk, die die Seite regulär öffnet. Also: in einem Netzwerk benutzen, das Sie kontrollieren, und den Bildschirm verlassen, wenn Sie fertig sind. Schritt für Schritt steht es auf der Seite Audio ohne iTunes übertragen.

Wann EarMemo nicht die richtige Wahl ist

  • Sie wollen den Quellcode lesen. EarMemo ist nicht Open Source. Alles oben ist von außen prüfbar – Datenschutzbericht, DNS-Protokoll, Proxy –, aber den Code können Sie nicht auditieren. Wenn das Ihr Maßstab ist: BookPlayer ist Open Source und eine vernünftige Antwort.
  • Sie wollen auch ohne Verbindung kaufen. Kauf und Wiederherstellung brauchen eine, weil StoreKit eine braucht. Was Sie schon haben, funktioniert ohne.
  • Sie wollen die Bibliothek auf jedem Gerät. Es gibt keine Synchronisierung, weil es keinen Server gibt, über den sie laufen könnte. Ihre Daten liegen in Ihrem eigenen iCloud-Backup, wenn Sie es aktiviert haben.
  • Sie wollen Podcasts in der App abonnieren. Ein Feed muss über das Netz geladen werden. EarMemo spielt Dateien, die Sie schon haben.

Häufige Fragen

Lädt EarMemo meine Audiodateien oder Notizen hoch?

Nein. Audiodateien, Notizen, Lesezeichen, Wiedergabeposition und Hörstatistik werden nur auf dem Gerät gespeichert. Es gibt keinen Entwicklerserver, der sie empfangen könnte.

Welche Netzwege hat EarMemo?

Drei: die optionale Wi-Fi-Übertragung im eigenen Netzwerk, Apple StoreKit für Kauf und Wiederherstellung und das Übergeben einer App-Store-URL an iOS, wenn Sie „EarMemo bewerten“ antippen. Import, Wiedergabe, Notizen, Statistik und Export nutzen keinen davon.

Warum fragt iOS EarMemo nach Zugriff auf das lokale Netzwerk?

Nur die Wi-Fi-Übertragung braucht ihn, deshalb wird er beim ersten Öffnen dieses Bildschirms erfragt und nicht beim Start. Lehnen Sie ab, bleibt der Rest der App unberührt.

Kann ich selbst sehen, was die App kontaktiert?

Schalten Sie Einstellungen → Datenschutz & Sicherheit → App-Datenschutzbericht ein und nutzen Sie die App ein paar Tage, beobachten Sie Ihr eigenes DNS-Protokoll, oder leiten Sie das Gerät über einen Proxy wie Proxyman, Charles oder mitmproxy.

Enthält die App SDKs von Dritten?

Nein. Das Projekt hat keine Abhängigkeitsdatei für CocoaPods, Carthage oder Swift Package Manager, und jedes eingebundene Framework stammt von Apple.
