# EarMemo

Marketing site for **EarMemo** — a private, offline-first iOS player for podcasts and audio notes.

Live at:
- **Canonical:** <https://earmemo.app/> — Cloudflare Pages (apex domain)
- **Redirect shell:** <https://earmemo.github.io/EarMemo/> — GitHub Pages serves only redirects to earmemo.app (see Hosting)

## App Store attribution

The homepage and tour use the existing `ct=officialsite` App Store campaign link. All generated answer pages share `ct=answerpage`: App Store Connect hides a campaign until it has 5 first-time downloaders, so per-page tokens would stay invisible at current volume. On a landing page with `utm_source=chatgpt.com` or a `chatgpt.com` referrer, `attribution.js` changes App Store buttons to one shared `ct=site_chatgpt` token. It does not set cookies, use storage, send events, or modify links to other destinations. The signal is lost if visitors navigate to another page before clicking. Per Apple's docs the campaign name is the token, so no registration is required (adding `site_chatgpt` in App Store Connect just makes it easier to find); see `GROWTH_EXPERIMENTS.md` for the measurement protocol. The links contain no user identifier and the website adds no analytics beacon or app telemetry. A campaign identifies the last qualifying App Store link, not the visitor's original ChatGPT referral with certainty.

Run `python3 tools/build-site-locales.py`, `python3 tools/build-answer-pages.py`, then `python3 tools/check-site.py` after changing pages, translations or the generators. It checks canonical URLs, sitemap coverage, all four hreflang targets, document languages, tour config keys/placeholders and storage namespaces, internal links, JSON-LD syntax and visible FAQ questions, the `404.html` rules (noindex, no canonical, root-absolute links), and a banned list of absolute network claims ("connect to any server", "不联网", …) the app cannot back up.

`404.html` is the apex site's error page: Cloudflare Pages serves it with HTTP 404 for any unknown path. The GitHub Pages mirror skips it and writes its own redirecting 404.

## Localization

The language menu links to the same page in English, Simplified Chinese,
Japanese and German. It uses native HTML details/summary and works without
JavaScript. Tour marks and resume position use a separate localStorage
namespace for each language. There is no automatic language redirect.

- `tools/build-site-locales.py` reuses English home/tour markup. Body text,
  accessible labels, demo attributes and metadata are translated during the
  build; pages need no runtime translation fetch. Unknown source text fails
  the build so new copy cannot silently appear in English.
- `tools/site-locales/home-{ja,de}.json` holds the home/tour copy keyed by
  English source text. `tour-{ja,de}.json` holds dynamic UI and export copy.
- `tools/build-answer-pages.py` renders all five guides in all four languages.
  Japanese/German editorial content is in `answers-{ja,de}.json`, and shared
  navigation/footer copy is in `ui-{ja,de}.json`.
- Japanese/German home/tour screenshots use real localized app captures,
  including localized library content. Their alt text describes those captures.
  The shared social-card image is still the English asset.
- `tools/build-answer-pages.py` also renders `/about` in all four languages.
- Privacy and localized plain-text pricing remain hand-written.

## Images

Marketing copy is **never baked into images** — every headline is real HTML text (selectable, translatable, crawlable). Device shots are the clean app UI only, framed in a CSS iPhone bezel.

Colours are the app's Cocoa tokens (`DESIGN.md` §2): cold-grey paper `#EEEFF1`, ink `#242527`, accent `#C9531A` (buttons, dots, the axis), `#AE4816` for accent-coloured text (4.9:1 on paper). The CSS keeps the app's token names (`--cream` is the paper). Change colours in `DESIGN.md` first.

- `tools/build-site-images.sh [RAW_DIR] [SITE_RAW_DIR]` — encodes web-weight WebP (900px wide, q82) into `img/<lang>/` from the raw real-UI captures that `tools/appstore/capture.sh` writes to `marketing/appstore/raw/iphone/<lang>/` (see `tools/appstore/README.md`; same screens as the App Store shots), plus the guide-only scenes `tools/capture-site-shots.sh <UDID> <en|zh|ja|de>` writes to `marketing/site/raw/<lang>/` (DEBUG launch routes on a dedicated simulator; the M4B scenes use a real silent .m4b made with `afconvert`). Requires `cwebp` (`brew install webp`). Guide pages place them with the generator's `figure` / `figures` blocks, next to the step each one illustrates.
- `tools/render-og.py` — renders `og.png` (wordmark + tagline + listening axis + framed `player` shot) with Pillow, from the same raw capture.

## Hosting

The same files are served from two places, out of one repo (`EarMemo/EarMemo`):

- **Cloudflare Pages → https://earmemo.app/** — the canonical site (apex domain). DNS for earmemo.app is on Cloudflare; the custom domain is set in the Cloudflare Pages dashboard (not via a repo file).
- **GitHub Pages → https://earmemo.github.io/EarMemo/** — a **redirect shell**, not a mirror. The github.io URL ranked first for the brand term before earmemo.app existed (bought 2026-06-17); serving redirects moves that weight to the apex instead of splitting it. `.github/workflows/pages.yml` runs `.github/build-redirects.py`, which turns every `*.html` into a 0-second `<meta refresh>` + canonical stub pointing at the **clean** apex URL (Cloudflare strips `.html`), writes one-line pointers for `llms.txt` / `pricing.md`, a minimal `robots.txt` with no sitemap, and a `404.html` that JS-redirects any other path. Images and `sitemap.xml` are not published there. Requires repo Settings → Pages → Source = **GitHub Actions**. There is **no `CNAME` file** on purpose: a CNAME file would make GitHub Pages seize earmemo.app.

All asset/navigation links are **relative** (`./icon.png`, `../privacy`, `./zh/`) and **extension-less** — Cloudflare Pages serves clean URLs and 307s `x.html` → `/x`, so no link, canonical, or sitemap entry may carry `.html`. Every page's `canonical`, Open Graph, and JSON-LD URLs are absolute and point at **earmemo.app**.

Deploy: `tools/sync-marketing-site.sh "<msg>"` pushes `site/` (including `.github/`) to the `EarMemo/EarMemo` repo; Cloudflare Pages deploys the real site from that push and the workflow rebuilds the redirect shell on GitHub Pages.

### Refresh Japanese/German device images

Use `SITE_LANGS="ja de" bash tools/build-site-images.sh RAW_DIR SITE_RAW_DIR`
to encode only these locales. `RAW_DIR/<lang>/` supplies `player`, `home`,
`episode-notes`, `history`, `wifi`, and `chapter-player` PNGs. The chapter
player comes from `tools/appstore/capture_chapters.py`; keep its
`chapter-source.json` alongside the raw capture for provenance.
`SITE_RAW_DIR/<lang>/headphones.png` comes from the current app:
run `tools/capture-site-shots.sh` with `ONLY=headphones` inside a temporary
`tools/simulator_pool.py run phone --temporary -- ...` lease, passing the
leased UDID and a Debug app path. Boot the leased device before capturing.
The same script supports `note-editor`, `export-locked`, and `offline` for
these locales; their guides currently have no screenshot figures.
After encoding, run `python3 tools/build-site-locales.py` and
`python3 tools/check-site.py`. The locale generator fails on missing captures.
