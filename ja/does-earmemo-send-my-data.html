EarMemo › ネットワークに何を送るのか

EarMemo はデータをどこかに送信しますか？ 通信経路のすべて

経路は3つ、どれもあなたのライブラリを運びません。任意の Wi-Fi 転送は iPhone 上に小さなウェブサーバーを立て、通信はご自身のネットワーク内で終わります。Pro の購入・購入の復元・評価シートは Apple StoreKit、つまり Apple のコードが Apple と通信します。設定の「EarMemo を評価」は URL を iOS に渡すだけで、開くのは App Store アプリです。取り込み、再生、メモ、統計、Markdown 書き出しは、この3つをどれも使いません。

EarMemo に開発者のサーバーはありません。音声・メモ・再生履歴を送る宛先そのものが存在しません。以下に全部を並べ、そのあとに、私の言葉を信じずに確かめる方法を挙げます。

最終更新 2026年10月15日 · 著者：Fan YANG（EarMemo 開発者）

アプリの通信経路は、この3つだけ

ライブラリを端末内に置くプレーヤーでも、ネットワークに触れる仕事はいくつか残ります。ファイルを入れる、支払いを受ける、リンクを開く。それぞれが、いつ動き、どこへ向かうのかを示します。

経路動くとき通信の行き先
Wi-Fi 転送（任意。画面を開くまで動きません）Wi-Fi 転送の画面を開いている間だけ。画面を離れるとサーバーは停止します。iPhone 上の素の HTTP リスナー（ポート 8080〜8090）。Bonjour で _earmemo-transfer._tcp として告知します。パソコンのブラウザから iPhone へ、ご自身のネットワーク内で完結し、ルーターの外には出ません。
Pro の購入、購入の復元、評価シートあなたが操作したとき、または iOS が評価シートを出すと判断したとき。Apple StoreKit、つまり Apple のフレームワークが Apple と通信します。アプリはカード番号を見ず、あなたを特定する情報も開発者には届きません。
設定の「EarMemo を評価」そのボタンを押したときだけ。apps.apple.com の URL を iOS に渡します。リクエストを出すのは App Store アプリで、EarMemo ではありません。
それ以外すべて（取り込み、再生、チャプター、速度、スリープタイマー、ブックマーク、メモ、統計、Markdown 書き出し）アプリを使っている間ずっと。どこへも向かいません。端末内のファイルを読み書きするだけです。

各行は 2026-10-21 に公開中のソースと照合しました。

アプリに入っていないもの

  • アカウントの仕組みがありません。サインインもなく、あなたを識別するものもありません。
  • アクセス解析、イベント記録、クラッシュレポートがありません。
  • リモート設定も、起動時に取得する機能フラグも、A/B 振り分けもありません。
  • 広告も、計測（アトリビューション）SDK もありません。
  • 第三者 SDK が一切ありません。CocoaPods・Carthage・Swift Package の依存ファイルを持たず、リンクしているフレームワークはすべて Apple 製です（AVFoundation、SwiftUI、StoreKit、WidgetKit、AppIntents、Network など）。
  • WebView がないため、アプリ内で外部のページが読み込まれることはありません。

アプリの外から確かめる4つの方法

自分で確かめられないプライバシーの説明は、言い方のうまい約束にすぎません。手間の少ない順に並べます。最初の方法は iPhone だけで足ります。

  1. 「App プライバシーレポート」をオンにする。設定 → プライバシーとセキュリティ → App プライバシーレポート。以後 iOS が、アプリごとに接続したドメインを記録します。EarMemo を数日ふつうに使ってから、その項目を見てください。接続したドメインがあれば、そこに並びます。
  2. 自分の DNS ログを見る。Pi-hole、NextDNS、あるいは問い合わせを記録するルーターがあれば、取り込み・再生・メモ・書き出しをしながら眺めてください。名前解決はサーバーに接続する前の最初の一歩で、自分のリゾルバからは隠しにくいものです。
  3. 端末をプロキシ経由にする。パソコンの Proxyman、Charles、mitmproxy に向けて、アプリの機能をひと通り動かします。通信が見えるのは購入のときだけで、それは Apple の通信です。StoreKit はアプリのプロセスの外で動きます。
  4. 初回起動から機内モードで使う。インストール後に機内モードにし、そのまま初めて開いて、「ファイル」から取り込み、再生、メモ、統計まで試します。サーバーに依存するアプリは初回起動でつまずくか、催促を出しがちです。この方法はアカウント不要のオフライン再生のページで詳しく説明しています。

証拠がもう2つ、私ではなく Apple 側にあります。EarMemo の App Store のプライバシー表示はデータを収集していませんで、アプリ内のプライバシーマニフェストはトラッキングを無効と宣言し、トラッキングドメインの一覧も収集するデータ種別の一覧も空です。どちらも開発者が Apple に対して行う宣言で、ウェブサイトの一文とは性質の違う証拠です。

開発側で走っているチェック

これはあなたには実行できません。ソースをお持ちでないからです。それでも、上の一覧が3つで止まっている理由はこれです。通信のコードを書く前にこの検索が空であること、それがこのプロジェクト自身の決まりで、私が従う指示書に書かれています。

$ grep -rn "URLSession\|URLRequest\|dataTask" --include="*.swift" \
    Sources ShareExtension SleepTimerWidget Shared
$   # 一致なし — 2026-10-21

URLSession はこの種のアプリが自ら外へ要求を出す道ですが、プロジェクト内に1か所もありません。唯一の import Network は Wi-Fi 転送サーバーで、アプリが開く外部 URL は自身の App Store ページだけです（URL を iOS に渡す残りの3か所は、どれも iOS の「設定」を開きます）。

Wi-Fi 転送サーバーの正体（都合の悪い部分も）

iPhone 上の小さな HTTP リスナーで、8080〜8090 のいずれかのポートを使い、パソコンがアドレスを打たずに見つけられるよう Bonjour で _earmemo-transfer._tcp として告知します。Wi-Fi 転送の画面を開くと起動し、離れると停止します。動いている間は、同じネットワークにいる人がそのアドレスを開けばファイル一覧を見てアップロードできます。ページが持つ起動ごとのトークンが防ぐのは、ブラウザ内の無関係なページが API を呼ぶことで、ページを正しく開いた同じネットワークの人は防げません。ですから、自分が管理しているネットワークで使い、終わったら画面を離れてください。手順はiTunes なしで音声を転送するページにあります。

EarMemo が向いていない場合

  • ソースを読みたい。EarMemo はオープンソースではありません。上の確認はすべてアプリの外からできますが、コードの監査はできません。それが条件なら、BookPlayer はオープンソースで妥当な答えです。
  • 通信なしで購入まで済ませたい。購入と復元には接続が必要です。StoreKit がそうだからです。すでに持っている機能は接続なしで動きます。
  • ライブラリを全端末に置きたい。同期はありません。同期するためのサーバーがないからです。データは、有効にしていればご自身の iCloud バックアップに含まれます。
  • アプリ内でポッドキャストを購読したい。フィードの取得には通信が必要です。EarMemo は取り込み済みのファイルを再生します。

よくある質問

EarMemo は音声やメモをアップロードしますか？

しません。音声ファイル、メモ、ブックマーク、再生位置、統計は端末内にのみ書き込まれます。受け取る開発者のサーバーが存在しません。

EarMemo の通信経路はどれですか？

3つです。任意のローカル Wi-Fi 転送、購入と復元のための Apple StoreKit、そして「EarMemo を評価」で App Store の URL を iOS に渡すこと。取り込み、再生、メモ、統計、書き出しはどれも使いません。

なぜ iOS がローカルネットワークの許可を求めるのですか？

必要なのは Wi-Fi 転送だけなので、起動時ではなくその画面を初めて開いたときに求めます。許可しなくても、ほかの機能に影響はありません。

アプリが何に接続しているか、自分で見られますか？

設定 → プライバシーとセキュリティ → App プライバシーレポートをオンにして数日使う、自分の DNS ログを見る、または Proxyman・Charles・mitmproxy などのプロキシ経由にする、のいずれかで見られます。

第三者 SDK は入っていますか？

入っていません。CocoaPods・Carthage・Swift Package Manager の依存ファイルがなく、リンクしているフレームワークはすべて Apple 製です。
